Dokumentasi · v1

Cara menggunakan PubAPI

Semua endpoint berada di bawah /api/v1. Request cukup curl; respons selalu JSON dengan amplop yang sama. Contoh di bawah memakai base URL default http://localhost:8080.

⚠ Hanya untuk pengujian yang diizinkan. Endpoint recon/scan melakukan koneksi aktif ke target yang Anda tentukan. Gunakan hanya pada aset milik sendiri atau yang punya izin tertulis.

MulaiIkhtisar

Server ditulis dengan Go + Gin. Jalankan dengan go run . atau make run; secara default mendengarkan di port 8080. Katalog endpoint machine-readable tersedia di GET /api, dan liveness di GET /health.

base urldefault
# landing page (HTML)
GET  http://localhost:8080/
# dokumentasi ini (HTML)
GET  http://localhost:8080/docs
# katalog endpoint (JSON)
GET  http://localhost:8080/api
# liveness probe
GET  http://localhost:8080/health

KontrakFormat respons

Setiap respons — sukses maupun gagal — memakai amplop yang sama sehingga mudah diparse secara seragam.

sukses200
{
  "success": true,
  "data": { /* payload */ },
  "timestamp": "2026-08-01T21:53:00Z"
}
gagal4xx / 5xx
{
  "success": false,
  "error": {
    "code": "invalid_input",
    "message": "Provide a valid ?domain="
  },
  "timestamp": "2026-08-01T21:53:00Z"
}

AksesAutentikasi & Akun

Akun (admin/client), API key, dan request logs tersimpan di SQLite. Alurnya: daftar/login → dapat session JWT → buat API key → panggil API dengan key. Kelola semuanya lewat Dashboard. Endpoint recon/scan wajib kredensial hanya jika AUTH_ENABLED=true (halaman publik /, /docs, /dashboard, /tos, /health, dan register/login selalu terbuka).

1 · Daftar / login (dapat session JWT)
POST /api/v1/auth/register · /auth/loginpublic
$ curl -X POST .../api/v1/auth/register \
     -d '{"email":"me@corp.com","password":"secret123","accept_tos":true}'
$ curl -X POST .../api/v1/auth/login -d '{"email":"me@corp.com","password":"secret123"}'
# -> { "data": { "token": "eyJ...", "user": { "role": "client" } } }
2 · Buat API key (pakai session JWT)
POST /api/v1/keysjwt
$ curl -X POST .../api/v1/keys -H "Authorization: Bearer $JWT" -d '{"name":"laptop"}'
# -> { "data": { "key": "pk_...", "note": "shown once" } }  (simpan sekarang)
3 · Panggil API dengan API key
authenticated request200 / 401
$ curl ".../api/v1/recon/dns?domain=example.com" -H "X-API-Key: pk_..."
# atau: -H "Authorization: Bearer pk_..."  (API key maupun JWT diterima)
# tanpa/keliru kredensial saat AUTH_ENABLED -> 401 unauthorized
Password di-hash bcrypt; API key disimpan sebagai hash SHA-256 (plaintext hanya ditampilkan sekali). JWT HS256 (JWT_SECRET), berlaku JWT_TTL_MINUTES. Endpoint login/register punya rate-limit lebih ketat (AUTH_RATE_*) untuk mencegah brute-force.
Admin (role admin) memiliki akses GET /api/v1/admin/users, /admin/logs, dan /admin/stats untuk melihat pengguna & siapa yang memakai API. Buat admin awal via ADMIN_EMAIL + ADMIN_PASSWORD.

ProteksiRate limit

Pembatasan token-bucket per alamat IP. Default 5 req/detik dengan burst 10. Saat terlampaui, server membalas 429 beserta header Retry-After: 1.

429 responserate_limited
{ "success": false,
  "error": { "code": "rate_limited",
            "message": "Too many requests. Please slow down." } }

PerformaCaching

Lookup eksternal yang lambat/rate-limited di-cache in-memory dengan TTL per-jenis, sehingga query berulang nyaris instan dan beban ke pihak ketiga berkurang. Aktif default; matikan dengan CACHE_ENABLED=false. Statistik di GET /health.

DataSumberTTL
DNS recordsresolver60 detik
Passive subdomaincrt.sh10 menit
Wayback URLsweb.archive.org1 jam
WHOISregistry6 jam
GeoIP + ASNip-api.com24 jam

ProteksiSSRF guard

Endpoint yang menyentuh jaringan (reverse-ip, scan/*, web/*) menolak target non-publik secara default: private, loopback, link-local, dan endpoint metadata cloud 169.254.169.254. Ini mencegah API publik disalahgunakan untuk menyisir jaringan internal Anda.

Untuk pengujian internal yang sah pada jaringan terisolasi, set ALLOW_PRIVATE_TARGETS=true. Jangan aktifkan pada deployment yang menghadap internet.

ModulRecon

Pengumpulan informasi domain & IP: DNS, subdomain, WHOIS, reverse DNS.

GET/api/v1/recon/dns

Resolusi record DNS umum (A, AAAA, CNAME, MX, NS, TXT) secara paralel.

Parameter (query)
NamaWajibKeterangan
domainwajibNama domain, mis. example.com
Contoh
requestcurl
$ curl "http://localhost:8080/api/v1\
/recon/dns?domain=example.com"
response200
{ "data": {
  "domain": "example.com",
  "a": ["104.20.23.154"],
  "ns": ["elliott.ns.cloudflare.com"],
  "txt": ["v=spf1 -all"] } }
GET/api/v1/recon/subdomain

Enumerasi subdomain dari dua sumber: brute (wordlist bawaan ~180 nama) dan passive (Certificate Transparency logs via crt.sh). Hasil digabung & dedup, dengan sumber & IP tiap temuan.

Parameter (query)
NamaWajibKeterangan
domainwajibDomain induk yang di-enumerasi
modeopsionalbrute · passive · both (default both)
Mode passive menemukan subdomain yang pernah menerima sertifikat TLS — jauh lebih kaya dari wordlist, termasuk nama non-generik. Nama historis yang tak lagi resolve tetap dicantumkan (resolved: false).
Contoh
requestcurl
$ curl "http://localhost:8080/api/v1\
/recon/subdomain?domain=github.com\
&mode=both"
response200
{ "data": {
  "mode": "both",
  "brute_tested": 180, "passive_found": 115,
  "found": 121,
  "subdomains": [
    { "subdomain": "api.github.com",
      "ips": ["140.82.112.6"],
      "sources": ["brute", "passive"],
      "resolved": true } ] } }

GET/api/v1/recon/email-security

Analisis postur anti-spoofing email: SPF, DMARC, DKIM (probe selector umum), dan DNSSEC. Menghasilkan grade A–F, flag spoofable, dan daftar temuan bertingkat.

Parameter (query)
NamaWajibKeterangan
domainwajibDomain yang dianalisis
selectorsopsionalSelector DKIM kustom, dipisah koma (mis. 20230601,mail). Digabung dengan daftar umum; maks 25.
Banyak provider (mis. Google) memakai selector khusus di luar daftar umum. Beri selectors= agar DKIM terdeteksi, mis. selectors=20230601.
Contoh
requestcurl
$ curl "http://localhost:8080/api/v1/recon/email-security?domain=google.com&selectors=20230601"
response200
{ "data": {
  "spf":    { "present": true, "all_qualifier": "~all", "policy": "softfail" },
  "dmarc":  { "present": true, "policy": "reject" },
  "dkim":   { "selectors_found": ["google"] },
  "dnssec": { "enabled": false },
  "grade": "C", "spoofable": false,
  "findings": [
    { "severity": "low", "message": "SPF hanya soft fail (~all)..." } ] } }

Parameter (query)

Contoh

response200

      "service": "GitHub Pages", "status": "vulnerable",
      "evidence": "fingerprint matched: There isn't a GitHub Pages site here" } ],
  "potential": [],

ModulScan

Pemindaian TCP dan pengambilan banner service. Tunduk pada SSRF guard dan batas MAX_SCAN_PORTS.

POST/api/v1/scan/ports

Port scan TCP konkuren. Bila ports kosong, memindai daftar port umum. Opsional mengambil banner service pada port terbuka.

Body (JSON)
FieldWajibKeterangan
hostwajibDomain atau IP target
portsopsionalSpec port, mis. "22,80,443,8000-8100". Default: port umum
banneropsionaltrue untuk banner grabbing
Contoh
requestcurl
$ curl -X POST http://localhost:8080/api/v1/scan/ports \
     -H 'Content-Type: application/json' \
     -d '{"host":"scanme.nmap.org","ports":"22,80,443","banner":true}'
response200
{ "data": {
  "host": "scanme.nmap.org", "scanned": 3, "open_count": 2,
  "ports": [

    { "port": 443, "open": false } ],
